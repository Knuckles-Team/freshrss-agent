# freshrss-agent development

This repository owns the FreshRSS Google Reader API facade, authentication
boundary, action-routed MCP tools, feed ontology and KG ingestion mappings, and
packaged connector content. Shared connector contracts, transports, TLS
profiles, and credential helpers belong to `scion-sdk`; admission,
serving, and durable graph state belong to their owning repositories. Read
`AGENTS.md` before changing code and keep credentials, private endpoints,
tenant data, and customer records out of source, logs, fixtures, and skill
content.

## Rapid delivery: the 5-minute contract

Specs are already designed. Deliver small, reviewable slices and cite the owning
spec row in the commit trailer.

- Find the owning row first with `git grep -n "<term>" -- specs` and extend the
  existing spec before adding requirement text.
- Reuse the single `Connector` in `freshrss_agent/__init__.py`, the facade in
  `freshrss_agent/api_client.py`, modular API clients under
  `freshrss_agent/api/`, and action-routed tools in `freshrss_agent/mcp/` plus
  `freshrss_agent/mcp_server.py`. Do not create a second API, MCP,
  authentication, or transport plane.
- Preserve `FRESHRSS_URL`, `FRESHRSS_USER`, `FRESHRSS_API_PASSWORD`,
  `FRESHRSS_TLS_PROFILE`, and `FRESHRSS_TLS_PROFILE_REF` handling in
  `freshrss_agent/auth.py`. Keep the existing optional OIDC delegation path
  (`ENABLE_DELEGATION`) and SDK TLS resolution; never print credentials or add
  a verification bypass.
- Keep the FreshRSS GReader API paths, cursor pagination, item normalization,
  subscription actions, and response models stable. Mock HTTP responses in
  tests; never call a live FreshRSS instance or use live credentials in a gate.
- Preserve best-effort typed/document KG ingestion in
  `freshrss_agent/kg_ingest.py`, source declarations in
  `freshrss_agent/connector_sources.py`, and neutral ontology mappings. Do not
  bypass the shared `scion_sdk.ingest` facade.
- Keep `skills/**`, `ontology/**`, prompts, and `mcp_config.json` coherent with
  package data and the `scion_sdk.connector` entry point
  (`freshrss-mcp = "freshrss_agent:connector"`). Generated `specs/*/status.json`
  files come from shared hooks; never hand-edit them.
- Every delivered requirement needs a bound focused test. This development
  skill binds to the central criterion `PIPE-CONNSPEC-R122.4`; it does not add a
  local status or rollup edit.

## Setup and gates

Use the pinned environment from `uv sync --locked`, then run the shared gates:

```bash
uv sync --locked
uvx pre-commit run --all-files
uvx pre-commit run --all-files --hook-stage pre-push
```

For focused feedback, run the smallest affected tests with the locked
environment, for example:

```bash
uv run --locked --extra test pytest -q tests/test_freshrss_development_skill.py
uv run --locked --extra test pytest -q tests/test_api_wrapper.py tests/test_auth.py
```

The canonical `.pre-commit-config.yaml` delegates connector-standard, secrets,
spec, tests-fast, and dependency-readiness to `Knuckles-Team/pipelines`. Do not
copy those hooks locally or bypass a failing check.

## Connector-specific checks

- Preserve GReader endpoint paths, action names, cursor semantics, and response
  normalization when changing Reader or subscription operations. Add focused
  mocked request tests for a changed provider path.
- Keep OIDC RFC 8693 token exchange and fixed API-password fallback at the
  existing authentication boundary. Resolve TLS policy through the SDK and do
  not bake static bearer tokens into the client.
- Keep feed items as searchable `Document` records and subscriptions as typed
  entities with their category relationships. Ingestion stays best-effort when
  the graph engine is unavailable.
- Keep `freshrss_agent/skills/`, `freshrss_agent/ontology/`,
  `freshrss_agent/connectors/`, prompts, and `freshrss_agent/mcp_config.json`
  in package data. Keep source metadata tenant-neutral.
- Documentation is published by the existing Pages workflow and dashboard
  configuration; source status records under `specs/` are generated by shared
  hooks.

## Packaging and publication

`pyproject.toml` declares the `scion_sdk.connector` entry point
`freshrss-mcp = "freshrss_agent:connector"` and packages `skills/**`,
`ontology/**`, `connectors/**`, prompts, and `mcp_config.json`. When packaged
content changes, inspect `uv build` output for
`freshrss_agent/skills/freshrss-agent-development/SKILL.md` and keep the public
version and editable lock entry coherent. This slice leaves the already-current
2.3.5 package metadata unchanged.

The canonical release caller delegates publication and connector rendering to
the shared pipelines. Do not commit generated Docker artifacts or claim
package, container, or Pages publication from a local build; require exact
source hosted evidence and the public artifact.

## Delivery discipline

Work in a real Git worktree based on `origin/main`. Inspect the complete diff,
stage only reviewed paths, and verify `git status --short` after every gate. Do
not use `git stash`, `git add -A`, or `git add .`; preserve unrelated working
tree changes. Keep runtime, ontology, status, and generated artifacts outside
this bounded skill slice unless the owning requirement explicitly requires them.
